# 722 Things To Build With AI Agents

A catalog of concrete, scoped, buildable projects. Every entry names a specific deliverable,
scores it on five axes, estimates effort, and states what it needs beyond a normal developer
workstation. No "build a chatbot" filler.

This is the public subset of a 1000-task catalog. 278 entries were removed because they
referenced personal, family, financial, or health details.

**[Browse all 722 entries, searchable and filterable](https://jesserweigel.github.io/722-things-to-build/)**

The site filters by category, effort and any of the five scores, searches titles and
descriptions, and links through to the ones that have actually been built.

## Why this exists

Most "AI project ideas" lists are 50 items long, written in a single pass, and converge on the
same handful of obvious apps. This one was generated by ten agents working in parallel against a
shared specification that explicitly instructed each of them to reject their own first ideas, then
filtered and indexed programmatically.

The result is uneven in places. Some entries are excellent and some are merely decent. That is the
honest tradeoff of generating at this volume, and the scores are there so you can filter.

## How to read an entry

```
### EVAL-026: Is temperature 0 actually deterministic?

**Scores:** $:1 CV:4 VIR:5 USE:3 ALT:4 | **Effort:** S | **Repo:** public

Run the same 200 prompts 20 times each at temperature 0 through Ollama, llama.cpp directly,
and HF transformers, with fixed seeds, and count divergent outputs and first-divergence token
position. Deliverable: a per-backend determinism report explaining batching and kernel
nondeterminism to people who assume greedy decoding is reproducible.

**Needs:** nothing
```

| Axis | Meaning |
|---|---|
| `$` | Money potential. 0 = none, 3 = plausible one-off sales, 5 = plausible recurring revenue |
| `CV` | Resume and portfolio value for a senior engineer |
| `VIR` | Would this get shared on HN, Reddit, or X |
| `USE` | Direct usefulness to the builder or to an agent fleet |
| `ALT` | Benefit to other people |

Effort: `S` under one agent-hour, `M` one to four, `L` four to sixteen, `XL` sixteen plus.

## The constraints these were written against

Entries assume a workstation roughly like this, so adjust if yours differs:

- One consumer GPU with 32 GB VRAM, running quantized models up to about 30B parameters
- A local Ollama instance with a mixed set of open models
- Free-tier access to a hosted frontier model for text, images, and speech
- No paid API budget worth speaking of

Entries that need more than that carry a `**Needs:**` line saying so.

## Health and finance entries

Health entries are information tooling with evidence grading and explicit "not medical advice"
framing. Nothing in this catalog diagnoses, prescribes, or substitutes for a clinician. Finance
entries are analysis and personal-automation tooling. None of them predict prices or constitute
financial advice.

## What has been built from it so far

29 entries in this catalog have been implemented, verified by running them, and published.
Each one is linked from its entry on the site, and the label is generated from a log of real
verify-command exit codes rather than written by hand, so nothing can be marked built without a
recorded passing run behind it.

## Regenerating the site

```bash
bash scripts/verify.sh                              # 9 checks, two of them negative controls
python3 tools/build_catalog_site.py --expect 722    # rebuild docs/index.html
```

The parser is deliberately strict: it refuses an entry it cannot fully account for rather than
skipping it. A regex parser that skips silently would produce a site that looks complete while
missing entries, and no amount of reading the rendered page would reveal it. Two of the verify
checks damage a copy of the catalog on purpose and require the build to fail, because the count
assertions would otherwise be passing vacuously.

Writing the parser found a real inconsistency: 70 entries use an `XL` effort tier. The README
documents it, the parser did not accept it, and the strict parse refused the whole file rather
than dropping 70 entries.
